# Multiverse credentials and setup

No paid service is required. Never commit `.env`, the Passport private key, database passwords, or the Flagsmith Organisation API token.

## Quick setup

1. Start Docker Desktop and wait until its engine is running.
2. If `.env` does **not** exist, run:

   ```powershell
   .\.venv\Scripts\python.exe scripts\generate_secrets.py
   ```

   The generator copies the template, fills locally generated secrets, and creates the Passport keys. Important: it does not overwrite an existing `.env`. If `.env` already exists with blank or development values, back it up and remove it before running the generator, or fill the values manually.
3. Start the stack with `docker compose up --build`.
4. Open `http://localhost:8000`, create the first Flagsmith administrator through the normal UI, and create an organisation.
5. Create `Multiverse Shop`, `Multiverse Learn`, and `Multiverse Workspace` projects. Give each a baseline environment and a separate Multiverse sandbox environment.
6. Obtain the Flagsmith credentials below, place them in `.env`, and restart the API and worker.

## Secrets generated locally

| Variable/file | Required | How to obtain | Exposure rule |
|---|---:|---|---|
| `AUTH_SECRET` | Yes | Generated by `scripts/generate_secrets.py`. | API/worker only. |
| `SESSION_SECRET` | Yes | Generated by the same script. | API only. |
| `CREDENTIAL_ENCRYPTION_KEY` | Yes | Generated as a URL-safe, Fernet-compatible 32-byte key. | API/worker only. Rotation requires migrating encrypted values. |
| `MYSQL_PASSWORD` | Docker | Generated by the script or chosen as a strong random password. | Must match `DATABASE_URL`. |
| `MYSQL_ROOT_PASSWORD` | Docker | Generated independently. | MySQL administration only; the app must not use root. |
| `FLAGSMITH_DB_PASSWORD` | Docker | Generated by the script. | Flagsmith/PostgreSQL only. |
| `FLAGSMITH_SECRET_KEY` | Docker | Generated by the script and used as Flagsmith's Django secret. | Flagsmith server only. |
| `infra/keys/passport_ed25519.pem` | Yes | Generated Ed25519 private key. | Private signing key; API/runtime only. |
| `infra/keys/passport_ed25519.pub.pem` | Yes | Generated with the private key. | Public; may be published through JWKS. |

The project does not currently need Google, GitHub, email-provider, payment, cloud, or LLM credentials. Those visible UI controls are not implemented integrations.

## Credentials obtained from Flagsmith

### `FLAGSMITH_MANAGEMENT_API_TOKEN` — private

1. Sign in to the self-hosted Flagsmith dashboard.
2. Select the organisation name in the top navigation.
3. Open **API Access**.
4. Select **Create API Key**.
5. Name it `Multiverse local control plane` and grant only the sandbox-project permissions it needs.
6. Copy it into `FLAGSMITH_MANAGEMENT_API_TOKEN` in `.env`.

Management API requests use `Authorization: Api-Key <token>`. Never put this token in browser code, a `VITE_*` variable, logs, screenshots, commits, or example configuration.

### Environment keys — evaluation keys

| Variable | Flagsmith project/environment |
|---|---|
| `FLAGSMITH_SHOP_ENV_KEY` | Multiverse Shop / Multiverse sandbox |
| `FLAGSMITH_LEARNING_ENV_KEY` | Multiverse Learn / Multiverse sandbox |
| `FLAGSMITH_WORKSPACE_ENV_KEY` | Multiverse Workspace / Multiverse sandbox |

For each project, select its sandbox environment, open **Environment Settings** / **SDK Keys**, copy the environment API key, and place it in the matching variable. Environment keys evaluate flags; they are not Organisation API tokens.

## URLs and non-secret configuration

| Variable | Docker value | Local non-Docker value | Notes |
|---|---|---|---|
| `APP_BASE_URL` | `http://localhost:5173` | same | Use the same hostname in the browser so cookies remain same-site. |
| `VITE_API_URL` | `http://localhost:8001` | same | Public frontend configuration. |
| `DATABASE_URL` | `mysql+pymysql://multiverse:<MYSQL_PASSWORD>@mysql:3306/multiverse` | `sqlite:///D:/toggle-hack/data/multiverse.db` | `mysql` resolves only inside Compose. |
| `REDIS_URL` | `redis://redis:6379/0` | `redis://localhost:6379/0` | Add Redis authentication outside local development. |
| `FLAGSMITH_API_URL` | `http://flagsmith:8000/api/v1/` | `http://localhost:8000/api/v1/` | Self-hosted Flagsmith API URL. |
| `PASSPORT_PRIVATE_KEY_PATH` | `/app/infra/keys/passport_ed25519.pem` | `./infra/keys/passport_ed25519.pem` | Private path. |
| `PASSPORT_PUBLIC_KEY_PATH` | `/app/infra/keys/passport_ed25519.pub.pem` | `./infra/keys/passport_ed25519.pub.pem` | Public verification key. |
| `PASSPORT_ISSUER` | `multiverse` | same | Not secret. |
| `PASSPORT_KEY_ID` | `multiverse-key-01` | same | Public identifier. |

`NEXT_PUBLIC_API_URL` and `FLAGSMITH_HOST_URL` are declared but not currently consumed. `DEMO_*_URL` values are reserved for sample applications that are not implemented yet.

## Verify without revealing secrets

1. Run `docker compose config --quiet`. Do not publish expanded Compose output because it may contain secrets.
2. Check `http://localhost:8001/health`, `/ready`, and `/api/v1/system/status`.
3. Run `python -m pytest -q` and `python scripts/audit_ui.py`.
4. Complete the mandatory two-concurrent-user Flagsmith isolation test before calling the integration production-ready; it remains pending.

## Rotation

- Create a replacement Organisation API token, update `.env`, restart API/worker, then revoke the old token.
- Coordinate database password changes with `DATABASE_URL` updates.
- Re-encrypt stored credentials before retiring `CREDENTIAL_ENCRYPTION_KEY`.
- Publish a new public Passport key under a new `PASSPORT_KEY_ID`; retain old verification keys until issued Passports expire.
